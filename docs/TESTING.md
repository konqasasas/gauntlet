# 1人で行う実機テスト

Minecraft Java 26.3で `127.0.0.1:25575` に接続し、OPで `/gauntlet kit` を実行してください。
本プラグインの実クライアント操作はまだ未検証です。以下の手順で操作感・表示・同期を確認します。

1. インベントリにアメジスト1個、スライムボール1個、専用の磨かれた安山岩64個が入ることを確認する。もう一度コマンドを実行して重複が増えないことを確認する。
2. 地面に立ち、視点を上下・左右に向けてアメジストをQで落とす。「CPを設定しました」と表示され、アイテムが落ちないことを確認する。Ctrl+Qでも確認する。
3. CPから移動してスプリントジャンプ中や落下中にアメジストを右クリックする。元の位置・視点へ戻り、移動の勢いと落下ダメージが持ち越されないことを確認する。
4. スライムボールでAdventureにする。通常の石へ専用ブロックを設置し、さらにその側面へ続けて設置する。歩行・ジャンプを挟んで高速に置いても64個に戻り、置いたブロックが残ることを確認する。メインハンドとオフハンドの双方で試す。
5. 専用足場の上でアメジストをQ。接地していても拒否され、以前のCPが維持されることを確認する。ジャンプ中にも拒否されることを確認する。
6. アメジストを空中とブロックに向けて右クリックする。どちらもCPへ戻り、自分の専用足場だけ消えることを確認する。
7. Creativeで通常の磨かれた安山岩を別途置く。専用足場と並べてリトライし、通常の安山岩だけ残ることを確認する。
8. スライムボールを1回ずつ右クリックして、AdventureとCreativeが切り替わることを確認する。両手に専用ツールがある場合も1クリックで2回切り替わらないことを確認する。
9. ハーフブロックやフェンス等の通常足場上でCP設定を試す。CPは足場を支える衝突形状と接地状態の両方で判定する。
10. 足場を置いてログアウトする。再接続して足場が片付いていること、CPへ戻れることを確認する。サーバー停止・再起動でも確認する。
11. CPを設定してAdventureでマグマへ触れる。自分のCPに視点・速度を戻して復帰し、自分の専用足場だけ消えて、残りの炎も消えることを確認する。マグマの端への一瞬の接触、ジャンプでの通過も確認する。通常の火では自動復帰せず、Survivalでは従来どおりマグマのダメージと燃焼があることを確認する。CP未設定の別ユーザーではTPや足場削除をせず、消火のみとなることを確認する。

## コース編集GUI

12. `/course` で一覧が開くことを確認する。GUI内のアイテムを通常クリック・Shiftクリック・ドラッグ・数字キーで取り出せないことを確認する。OPでないユーザーでは開けないことを確認する。
13. 編集画面から杖を受け取り、左クリック・右クリックで2点を選ぶ。Creativeで左クリックしてもブロックが壊れないこと、オフハンドのブロックが置かれないことを確認する。杖を持つと黄色の枠が見えることを確認する。
14. 一覧の「新規作成」でIDを入力する。チャットに発言が流れないこと、大文字が小文字になること、使えない文字・既存IDが拒否されること、「キャンセル」で中止できることを確認する。
15. 範囲を設定して水色の枠を確認する。範囲外・空中でのスタート設定が拒否され、範囲内の接地で成功することを確認する。黄緑の柱と「スタート地点へ移動」の向きを確認する。
16. 制限時間を左／右／Shiftクリックで変え、0〜600秒に収まることを確認する。状態の切り替え、名前変更を確認する。
17. サーバーを再起動し、設定が残っていることを確認する。削除して `courses\deleted\` に退避されることを確認する。

## 参加者モード（本番）

18. ダイヤモンドブロックの上で「ゴールを登録／解除」を押し、白枠が出ること、もう一度押すと解除されることを確認する。ダイヤモンド以外・空中・範囲外では拒否されることを確認する。
19. 所持品を持った状態で「参加者モードで遊ぶ」。スタートへ移動し、Adventure、初期装備（既定は1番に専用足場）と5番の切り替えアイテムだけになることを確認する。アクションバーが「動くと計測開始」であること。
20. 視点だけ動かしても始まらないこと。歩く／ジャンプ／その場でブロック設置・右クリック・左クリックのそれぞれで計測が始まることを確認する。
21. ゴールのダイヤモンドに乗ってタイトル・チャットのタイムを確認する。2回目以降で自己ベストとの差が出ることを確認する。8番でリトライ、9番で終了できることを確認する。
22. 計測中に1番でQ：スタートに戻り、置いた足場が消え、計測が待機に戻ることを確認する（Qのスイングで即計測開始にならないこと）。2〜4番でQしても何も起きないこと。
23. インベントリでアイテムを動かせない・Fで持ち替えできないことを確認する。
24. `/course leave` とログアウトのそれぞれで、元の位置・ゲームモード・所持品に戻ることを確認する。
25. 運営でないユーザーで `/course play <ID>` を実行し、「完成」以外のコースは拒否されることを確認する。
26. `records.jsonl` にクリア・リタイアが追記されていることを確認する。

## 失敗条件・トリガー・練習

27. 本番でマグマに一瞬触れる／範囲外へ出る／制限時間を超える／死亡する。それぞれ「失敗：〜」と出てスタートに戻り、足場・mob・装備がリセットされ、`records.jsonl` に FAIL が残ることを確認する。編集画面でマグマ・範囲外をオフにすると失敗しないことを確認する。
28. テンプレート画面で「手持ちのアイテムを登録」とワンクリック追加（メイス等）を試す。耐久値無限の切り替え・名前変更・Shift＋右クリック削除を確認する。
29. 初期装備で2番にメイス（ウィンドバーストⅡ）を設定し、参加時に2番に入り、耐久値が減らないことを確認する。1番を空にすると編集画面に警告が出て参加できないことを確認する。
30. 鉄の感圧板の上で「足元のトリガーを編集」。アイテム付与（1番を上書き／2〜4番指定／空き）・アイテム削除（全レベル／指定レベル）・mob（例：summon minecraft:strider ... をそのまま貼る）・サウンド（試聴・音量・音程）を追加し、踏むと1回だけ実行されることを確認する。同じアイテムを持っていると渡されないこと、レベル違いなら渡されることを確認する。
31. スタートに戻ると mob が消え、もう一度踏むと再び出ることを確認する。サーバーを再起動しても mob がワールドに残らないことを確認する。
32. 5番で練習へ。7番でセーブ（空中・飛行中は拒否）。足場を追加で置いてから1番でQ：セーブ地点へ戻り、セーブ前の足場は残り、後の足場だけ消えること。持ち物・mob・トリガーの発火状態もセーブ時に戻ることを確認する。
33. 練習で6番の飛行をオンにして飛び、区間タイムが「無効」になること、ロード後に飛ばずに次のトリガーかゴールまで行くと区間タイムが出ることを確認する。練習では時間切れにならず、記録も残らないことを確認する。
34. 練習中にマグマ・範囲外で失敗するとセーブ地点に戻ることを確認する。5番で本番に戻るとスタートからになり、セーブが消えることを確認する。

## サーバー上の自動確認（クライアントなし）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\verify-server.ps1 -Action features
```

実際のPaperで、テンプレートからのメイス生成（ウィンドバースト・耐久値無限・内部タグ）、設置用ブロックの判定、貼り付けた summon のSNBT適用、mobのタグ付け・削除・スナップショットからの再生成、騎乗mobの追跡を確認し、一時テンプレートとmobを片付けます。成功時は `FEATURE_PASS` と `FEATURE_CLEANUP_PASS` をログに出します。

チェスト等の側面へ設置する場合は通常どおりスニークして操作します。Adventureの専用ブロックも、プレイヤーに重なる位置や既存の固体ブロック内には設置できません。
現在のサーバーの初期ゲームモード設定は以前のSURVIVALを引き継いでいます。最初にスライムボールを2回使えばAdventureになります。

## ログと不具合報告

`run\paper-26.3\logs\latest.log` に起動・CP設定・保存失敗を記録します。
不具合時は時刻、ゲームモード、メイン／オフハンド、操作したブロック、起きた現象を残してください。
CP保存データは `plugins\ParkourGauntlet\state.json` です。起動中の手編集は避けてください。

## ローカルサーバーの自動確認

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\verify-server.ps1
```

実際のPaper上でネイティブアイテム・衝突形状を確認し、プレイヤー操作は模擬オブジェクトで検証します。
既存地形を避け、スポーン付近の上空4ブロックが空気であることを確認してから一時的に使用し、終了時に元へ戻します。
模擬プレイヤーの状態も削除します。ローカルJava Attachを使う開発専用ツールで、配布JARには含めません。
成功時は `INTEGRATION_PASS` と `INTEGRATION_CLEANUP_PASS` をログに出力します。JDKの動的エージェント読み込み警告はこの補助ツールによるものです。

模擬データでの所有者分離は2クライアントの実証ではありません。将来の複数人テストではA/Bがそれぞれ足場を設置し、AのリトライでBの足場が残ることを確認します。レーン・ゴーストは今回の対象外です。
