# デザイナー向けエディターの実装計画

作成: 2026-10-18（revision 73 時点）

進み具合: **段階A・B・C 完了、段階D は D1（部品の仕組み）まで完了**（2026-10-18）。データの版は 6。次は D2（既存の16画面を部品で作り直す）。説明書は [designer-guide.md](designer-guide.md)。

デザイナーがブラウザーのエディターだけで画面を作り、見た目を自由に変えられるようにする。プラグイン（Gauntlet）は書き出しの形が変わらない限り触らない。

## 決めたこと

| 項目 | 決定 |
|---|---|
| 部品の方式 | マスターと使用箇所（Figma のコンポーネントと同じ考え方）。マスターを直すと全画面に反映。使用箇所ごとに変えられるのは、文字・幅と高さ・押したときの動作・ツールチップ・見た目の種類（バリアント） |
| 操作の作法 | Figma に寄せる（Shift で複数選択、Ctrl+G でグループ、Ctrl+C/V、Alt+ドラッグで複製、スマートガイドなど） |
| 既存の16画面 | 部品の仕組みができたら、全部部品で作り直す（見本のスクリプトを書き直す）。見た目は今と画素単位で同じにする |
| 順番 | 土台から: 4 → 2 → 3 → 1 → 5 |

## 全体の方針

- **書き出し（compile）は変えない。** グループ・部品・文字スタイルは、書き出しの直前に「今と同じ平らな要素の並び」へ展開する（テーマの色を `resolveScreen` で実際の色にしているのと同じ場所）。書き出しの形・検証・プラグインはそのまま使える。
- **データの版を上げる（schemaVersion 4）。** 新しい項目（グループ・部品・文字スタイル・9分割）は `migrateProject` で既存のデータに足す。
- **操作（ops）を先に作り、画面はその上に作る。** CLI・API からも同じことができるようにし、テストも ops で書く。
- **各段階の終わりに「既存の画面の書き出しが変わっていない」ことを確かめる。** 書き出しの雛形（templates）と画像タイルを、段階の前後で比べる。

## 段階A（4）: 編集の基本操作

### 内容

- **複数選択**
  - Shift+クリックで追加・解除。何もない所からドラッグすると、範囲で選択する。Ctrl+A で全選択。
  - 複数を一緒に移動・大きさの変更（比率で拡大縮小）・削除・複製できる。
  - 値を変える欄は、選んだ要素に共通する項目だけ出す（値が違えば「混在」と表示）。
- **整列・等間隔**: 左・中央・右・上・中央・下に揃える、横・縦に等間隔に並べる。基準は選択範囲（Shift+クリックで基準の要素を指定できるようにする）。
- **スマートガイド**: ドラッグ中に、ほかの要素の端・中心や画面の中心に吸着して線を出す。9px 行への吸着は今どおり。
- **グループ**
  - Ctrl+G でまとめる、Ctrl+Shift+G で解除。入れ子も可。
  - クリックでグループ全体を選び、ダブルクリックで中に入って個別に選ぶ（Figma と同じ）。
  - 重なり順の一覧は木の形で表示し、ドラッグで並べ替え・グループへの出し入れができる。
- **コピーと貼り付け**: Ctrl+C / Ctrl+V。画面をまたいでも、ブラウザーのタブをまたいでも使える（OS のクリップボードに JSON で入れる）。貼り付けると id は自動で付け直す。
- **文字スタイル**
  - 「見出し」「本文」「小さい文字」「ボタンの文字」などを登録し、文字の要素から参照する。
  - スタイルを直すと、それを使う文字すべてに反映される。テーマの色と同じ画面で管理する。
- **細かい改善**
  - Alt+ドラッグで複製
  - ロック・非表示の一括切り替え
  - 要素の名前を一覧で直接変更
  - 選んだ要素の座標・大きさを画面上に表示

### データ

- 画面に `groups: [{ id, name, parent, locked, visible }]` を足し、要素に `group`（所属するグループの id）を足す。要素の並び自体は今どおり平ら（重なり順は配列の順）で、グループは見た目と選択のための情報。中身がなくなったグループは自動で消える。非表示のグループの中は書き出しにも出ない。
- プロジェクトに `textStyles: { id: { name, render, fontFamily, fontSize, pixel, bold, color, shadow, shadowColor, align, valign, lineHeight, wordSpacing } }` を足し、文字（とボタンのラベル）に `textStyle` を足す。スタイルを指定した文字は、スタイルの値を使う（要素ごとに一部だけ上書きする形はとらず、「切り離す」で要素の値に戻す。Figma と同じ）。

### 操作（ops）

- 複数の要素をまとめて変える: `patch_elements`（id の一覧と値）
- グループ: `group_elements` / `ungroup` / `set_group`
- 貼り付け: `paste_elements`（要素とグループのまとまりを、id を付け直して追加）
- 文字スタイル: `set_text_style` / `rename_text_style` / `remove_text_style`（使用中は消せない）
- 整列・等間隔は画面側で座標を計算し、`patch_elements` で送る（1回の操作で元に戻せる）。

### 確認

- ops ごとのテスト（元に戻せること、検証に失敗したら何も変わらないこと）。
- ブラウザーでの手順確認（複数選択 → 整列 → グループ → 別の画面へ貼り付け → 元に戻す）。

## 段階B（2）: 状態の編集

### 内容

- **要素に状態を付ける欄**: 名前（既存の名前から選ぶか新しく入力）、「＝」か「≠」、値。グループにも付けられ、中の要素すべてに効く。
- **画面の状態の一覧**
  - その画面で使っている状態の名前と値、既定値を表で表示・編集する（`stateDefaults`）。
  - 名前の変更は、使っているすべての要素に反映する。
- **プレビューの値の切り替え**
  - 「今どの値で見るか」を画面の上部で選べる（既定値とは別。データは変えない）。
  - 編集画面・プレビュー・検証のすべてがその値で表示する。
- **見えていない要素は選べない**
  - 今の値で見えていない要素は、画面上でクリックしても選ばれない（今は重なった別の状態の要素を掴めてしまう）。
  - 重なり順の一覧では薄く表示し、状態を記号で示す。
- **「この状態の見た目を作る」**: 選んだ要素（グループ）を複製して、別の値の状態を付ける操作。例: 「選択中」の見た目から「選択していない」見た目を作る。

### データ・サーバー

- グループの `state` を足す（展開時に中の要素の条件として扱う。要素自身にも条件があれば両方を満たすときだけ表示）。条件は `&` でつなげるようにし（`tab=a&muted=off`）、プラグインの `DialogTemplates.matches` も対応した。
- 新しい状態の名前を使ったとき、既定値がなければ条件の値を既定値として自動で入れる。値の切り替え欄には「（ほかの値）」（`_other`）を置き、≠ の見た目を確かめられるようにした。
- 状態の名前を変える op: `rename_state_key`
- プレビューと検証の API に `?state=名前:値,...` を足し、`buildScreen` に表示する値を渡せるようにする（今は既定値に固定されている）。

### 確認

- 既定値以外の組み合わせを画素単位で照合する仕組み（今回作った確認用のスクリプト）を、テストに入れる。

## 段階C（3）: 画像の9分割

### 内容

- 画像の置き方に「9分割」を足す。四隅は伸ばさず、上下の辺は横だけ、左右の辺は縦だけ、真ん中は両方向に伸ばす（並べる・伸ばすを選べる）。
- 分割位置（上下左右の余白）は、素材の一覧で画像ごとに決めておき、要素ごとに上書きもできる。素材の画面で分割線をドラッグして決める。
- 画像の倍率: 画像の1画素を何 GUI px で描くかを選べるようにする（今の素材は `textureScale` 倍で描かれる前提があいまいなので、ここで決める）。
- ボタンの画像にも同じ置き方を使えるようにする。
- 素材の一覧を整える（大きいサムネイル、名前の変更、使っている場所の一覧、差し替え）。

### データ

- 素材に `slice: { l, t, r, b }` と `pixelScale` を足す。
- 画像（とボタン）の `fit` に `nine` を足し、要素ごとの `slice`（省略時は素材の値）を足す。

### 確認

- 9分割の描画のテスト（角が崩れないこと、最小の大きさより小さい場合の扱い）。

## 段階D（1）: 部品（コンポーネント）

### 内容

- **部品のマスター**
  - プロジェクトに部品の一覧を持つ。部品は専用の編集画面で、今の画面と同じ道具（四角形・画像・文字・クリック領域・グループ・状態）で作る。
  - **差し込み口（プロパティ）**: 使用箇所ごとに変えられる値を決める。例: 「ラベル」（文字）、「動作」（クリックの action）、「説明」（ツールチップ）、「アイコン」（画像）。部品の中の要素の値を、差し込み口に結び付ける。
  - **バリアント**: 「通常」「選択中」「危険」「無効」のような見た目の種類を、部品の中で要素に付ける（状態と同じ仕組みで、名前が `variant`）。
  - **伸び縮みの指定**: 使用箇所で幅や高さを変えたとき、中の要素をどう動かすか。左右それぞれ「左に固定」「右に固定」「両端に固定（伸びる）」「中央」「比率」、上下も同様（Figma の制約と同じ）。9分割の画像と組み合わせれば、どの幅でも崩れないボタンが作れる。
- **使用箇所（インスタンス）**
  - 新しい要素の種類 `instance`。部品・位置・大きさ・バリアント・差し込み口の値を持つ。
  - **バリアントを状態に結び付ける**: 例: 「ui_lang が auto なら『選択中』、それ以外なら『通常』」。今の見本の `variant()`（同じボタンを状態ごとに2回描く）を、部品の設定1つで書けるようにする。
  - 操作:
    - 部品の差し替え
    - 部品から切り離す（ただの要素に戻す）
    - マスターへ移動（ダブルクリックで部品の編集画面へ）
    - 使用箇所での上書きを元に戻す
- **最初から用意する部品**: 今の見本の部品を、部品として作り直す。
  - ボタン（通常・選択中・危険）
  - タブ
  - 閉じる✕
  - スイッチ
  - スライダー
  - 選択欄（▼）
  - カード
  - 見出し帯
- **書き出し**: 使用箇所は、書き出しの直前に平らな要素へ展開する。展開後の要素の id は `使用箇所の id__部品の中の id` の形で決まる（書き出しのたびに同じになる）。

### データ

- プロジェクトに `components: [{ id, name, width, height, elements, groups, props: [{ name, type, default }], variants: [名前...], bindings, constraints }]` を足す。
- 要素の種類 `instance`: `{ component, x, y, w, h, variant, variantBy: { key, map: { 値: バリアント }, else: バリアント }, props: { 名前: 値 }, overrides }`。
- 展開の処理は `lib/components.mjs` に置き、ブラウザーと Node の両方で使う（`model.mjs` と同じく依存なし）。

### 既存の画面の作り直し

- 見本のスクリプト（`examples/*_mock.mjs`）を、部品を作る部分と、画面に使用箇所を置く部分に書き直す。
- 作り直した後の書き出しが、今の書き出しと画素単位で同じになることを確かめる。展開後の要素の並び・id は変わってよいが、画像タイルと書き出しの見た目・クリック範囲は同じ。
- 画面の要素の数は、設定画面で 373 → 数十個程度になる見込み。

### 確認

- 展開のテスト（伸び縮みの指定、バリアント、差し込み口、状態への結び付け）。
- 全画面の作り直し前後の比較。

## 段階E（5）: その場の警告

### 内容

- 警告を要素に結び付けて、画面上に印（赤: 書き出せない、黄: 注意）を出す。印に乗せると内容、クリックでその要素を選ぶ。
- 下の一覧の項目をクリックすると、その要素を選んで画面をそこへ寄せる。
- その場で分かるものは、ドラッグ中から表示する。
  - ゲーム内フォントの文字が9px行からずれている
  - クリック範囲が見た目とずれる
  - 画面からはみ出す
  - 状態の既定値がない
- 書き出しの検証（画素の照合・クリック範囲・行の幅）は、今どおり少し待ってからサーバーで行い、結果を印で出す。
- 見た目の点検（中央ずれ・はみ出し・重なり）を、既定値だけでなく状態ごとに行う。

### データ・サーバー

- 警告を文字列から `{ element, kind, severity, message, box }` の形に直す（`buildScreen` と `audit.mjs`）。CLI の表示は今と同じ文にする。
