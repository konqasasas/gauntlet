# メニュー（Dialog）

メニューの画面は Dialog エディター（`dialog-editor/`、もとは別リポジトリの dialog-custom-gui）で作る。このプラグインは、エディターが書き出した雛形からプレイヤーごとの画面を組み立てて送り、画面のクリック（custom）を受けて処理する。エディターからの引き継ぎ資料は [dialog-editor/docs/plugin-handoff.md](../../dialog-editor/docs/plugin-handoff.md)。

状態（2026-10-18）：接続済みは「画面の移動・閉じる・ロビーへ戻る・エモート・設定」。設定画面は選択中の項目・ON/OFF・音量・翻訳先がプレイヤーの値で表示される。ほかの画面の中身は固定の見本。

## 置くもの

エディターで書き出した `exports\latest\` から:

| ファイル | 置き場所 | 用途 |
|---|---|---|
| `templates\*.json` | `plugins\ParkourGauntlet\menu\` | 画面の雛形（全状態入り）。プラグインが読む。`/gauntlet reload menu` で読み直す |
| `resourcepack.zip` | クライアント（配布の仕組みはまだない） | 画像タイルとフォント |
| `datapack.zip` | ワールドの `datapacks\`（任意） | 雛形から組み立てられない画面（入力欄のある `course_search`）だけに使う。ほかの画面は不要 |

- 名前空間 `dcg` は `ui/DialogMenu.NAMESPACE`。エディターの設定で変えたら合わせる。

## 画面の組み立て（`ui/DialogTemplates`・`ui/DialogMenu`）

- 雛形は Dialog の JSON で、状態ごとの部品に `insertion` の目印 `dcg:state:<条件>` が付いている（条件は `名前=値` か `名前!=値`）。各部品は「描いて元の位置に戻る」形なので、合わない部品を取り除いても行の幅は変わらない。
- 状態の値はプレイヤーの個人設定（`Settings.ALL`）。真偽値は `on` / `off`、数値は `70` のような文字列。
- 取り除いた後の JSON を Adventure の `GsonComponentSerializer` で読み、Paper の Dialog API（`Dialog.create`）で組み立てて送る。データパックへの登録は使わない。
- Adventure は custom クリックの payload を SNBT の文字列としてしか読まないため、JSON の payload は SNBT に直してから読む。
- 組み立てられるのはフッターなしの `dialog_list` だけ。それ以外（入力欄のある画面）は、データパックで登録された同じ ID の画面を開く。どちらもなければチャットで知らせ、ログに警告を出す。

## 入口

- `/menu` で `top_menu` を開く。
- （2026-10-18 決定、未実装）ホットバー9番をメニューのアイテムにする（ロビー・本番・練習で共通）。ロビーの7番にエモートのアイテムを置き、エモートのリングを直接開く。`/emote` でも開ける。[hotbar-and-settings.md](hotbar-and-settings.md) のホットバー。

## 導線の方針（2026-10-18 決定、画面は未修正）

今の画面（エディターの16画面）を見直し、Minecraft 以外のゲーム・アプリの普通のUIを手本にして決めたこと。画面の修正はまだしていない。各項目の「Dialog での形」は今の見込みで、作るときに確かめる。

### 全体の構造: 上に常にタブ

```
[ ホーム ] [ コース ] [ ランキング ] [ プロフィール ]          [⚙] [🔔3] [✕]
```

- どの画面でも上の行に同じタブを置き、別のタブへ1手で移れるようにする。今の「トップから各画面へ行って、メニューへ戻る」形（ハブ型）と「メニューへ戻る」ボタンはやめる。
- 設定（⚙）とお知らせ（🔔、未読数のバッジ付き）は右上のアイコンにする。
- Dialog での形: 全画面に同じタブの行を置き、押したら画面を送り直す。今のタブは選んだ状態で表示する。

### ホーム（今の `top_menu`）

- 一番大きいのは「続きから挑戦（RANK・ステージ）」。その下に最近の記録・新しいお知らせ・おすすめのコースなど、「次にやること」を並べる。
- ホームはロビーでもコース中でも同じ。**コース中の操作**（辿り直す・セーブ・練習と本番の切り替え・1つ前のセーブに戻す・コースを抜ける）は**アイテムで行い、メニューには出さない**（2026-10-18 見直し。ポーズの画面はやめた）。
- エモートはメニューからは開かない（導線は別に決める。2026-10-18 見直し）。

### エモート: リング

- 画面の中央に8枠をリング状に並べ、押すと再生して閉じる。ロビーの7番か `/emote` で直接開く。
- 枠に何を置くかはプレイヤーが決める。別の「エモートの管理」画面で、持っているエモートの一覧から枠に置く。
- Dialog での形と理想との差:
  - 理想は「キーを押している間だけ出て、向けた方向を離して決める」（Fortnite・Apex の形）だが、Dialog はキーやマウスを放したことをサーバーに伝えられないので、「開く → クリック」の2手になる。
  - カーソルを当てた枠を光らせることはできない（ホバーで出せるのはツールチップだけ）。名前はツールチップで出す。
- 今のタグ（すべて / 動き / ポーズ）の3画面はやめる。

### 入力部品の選び方

| 選択肢 | 部品 | 例 |
|---|---|---|
| 2択 | トグル | 自動翻訳 |
| 3〜4択 | セグメント（横並びのボタン） | コースの並べ替え |
| 言語・5択以上 | ドロップダウン（画面の上に重ねて開く一覧） | UI言語、翻訳先（15言語） |
| 数値 | スライダー（目盛りのクリック ＋ ◀ ▶） | 音量 |
| 絞り込み | チップ（複数同時に ON にできる小さなボタン） | コース選択 |

- ドロップダウン: 「一覧が開いている」状態（例 `translate_open=on`）の重ね絵で作る。開いている間は、下の行のクリック範囲を状態で消す。言語はその言語の表記で並べる（日本語 / English / 한국어 …）。
- スライダー: つまんで動かす（ドラッグ）はできないので、目盛りのクリックで値を決める。値を変えたらその音量で試しの音を鳴らす。Dialog 標準のスライダー（`number_range`）は確定ボタンを押すまで値が届かないので使わない。
- Dialog 標準の選択肢（`single_option`）は押すたびに次の値に変わるだけなので使わない。
- 状態が変わるたびに画面を送り直すので、スクロール位置は先頭に戻る。画面はスクロールが要らない高さに収め、長い一覧はページ送りにする。

### コース選択（コースのタブ）

- 絞り込みはチップにし、複数を組み合わせられるようにする（例: `未クリア` `★1〜2` `お気に入り`）。Dialog での形: チップごとに ON/OFF の状態を持ち、押すたびに送り直す。
- 並べ替え（難易度順 / 新着順 / 名前順）はセグメント。
- カードを押してもすぐには始めず、**コースの詳細**（ベスト記録・そのコースのランキング・お気に入り・開始ボタン）を出す。カードの角のお気に入りの★を押し損ねてコースに移動する誤操作をなくし、コースごとのランキングへの入口にもする。

### 設定

- 左にカテゴリ、右に項目（今の形）。上に**設定の検索欄**を置く。
  - Dialog での形: 入力欄 →「検索」ボタン → 当てはまる項目をハイライトし、「解除」で戻す。打つたびにその場で絞り込むことはできない（文字はボタンを押したときにしか届かない）。
  - 今のプラグインは入力欄のある画面を組み立てられない（フッターなしの `dialog_list` だけ）。検索欄のためにその対応が要る。
- 「翻訳」を1つのまとまりにし、「自動翻訳 → 翻訳先」の順に並べる。自動翻訳が off のときは翻訳先をグレーにする。翻訳先の別画面（`settings_translate`）はやめてドロップダウンにする。
- 「プロフィール設定」は設定の「プロフィール」カテゴリに移し、プロフィールは見るだけの画面にする。

### ランキング・プロフィール

- 役割の分け方: ランキング＝他人と比べる（コースごと。コースの詳細からも入れる）、プロフィール＝自分の進み具合（ランク・クリア数・実績）。

### 初めての人

- 初めて参加したときに1回だけ、短い案内（言語 → 操作（Q・F）→ ランクアップ開始）を出す。UI言語の初期値が「自動」なので、最初に言語を確かめてもらう。「遊び方」の画面はメニューからも開ける。

## 世界観との対応（2026-10-18、画面は未修正）

資料「Catena 世界観設定」（2026-10-18、リポジトリの外）の各設定を、GUI で表すものと世界の中で表すものに分けた。具体的な色や枠の形は、世界観の資料にある「デザインルールは建築担当と相談して決める」のあとで決める。

### GUI で表すもの

| 設定 | 画面 | 表し方 |
|---|---|---|
| Anulus I〜XI と「鎖を遡る旅」（一本道、下がらない、国土とランクが一致） | ランクアップの進行マップ | 11個の輪を縦に連ねた鎖。下が Anulus I（新しい時代）で、上ほど古い。最上部は途切れ、その先に Origo。輪を押すと、その時代の約10の Limen と最後の Culmen がノードで並ぶ。つないだ輪は色付き、この先は鍵付き。背景の空は奥ほど昼 → 夕暮れ → 黄昏 |
| 「名が刻まれる」文化、名簿・印刷・地図 | ランキング、プロフィール | ランキングは守り手の組織の名簿・台帳として、近世の印刷物の意匠で見せる。プロフィールは自分の鎖（つないだ輪の数）と記録帳。ランクは名前の色と「Anulus III」の表記だけで表し、称号は出さない |
| 市井の試練（プレイヤーが架けた道。辿られるほど価値が出る。出せるのは一定のランク以上） | コース選択（ランクアップ以外）＝展示場 | カードに挑戦された回数を出し、並べ替えに「人気順」を足す。作る側の入口に、鍵とランク条件を出す |
| ゴシックは正統な試練の側だけ | 画面ごとの枠 | ランクアップの進行画面だけをゴシックの枠（尖塔・小尖塔）にし、展示場の画面は落ち着いた別の意匠にする。「尖塔が見えたら由緒ある試練」を GUI でも守る |
| Umbra（ゴースト） | ランキング | 「ゴーストと走る」を「Umbra と辿る」とする |
| 守り手の組織（記録と保守の組織） | お知らせ | 守り手からの布告・掲示として見せる。宗教色は薄く、役所の掲示の扱い |
| 相棒（能力は全員同じ。姿と種の名前は未定） | 姿・種類の選択、着せ替え、プロフィール | 姿が決まったら選ぶ画面を作る。性能の比較は出さず、見た目と関係の深さ（親密度）だけを扱う |

### 文言と見た目の決まり

- 固有名詞はラテン語のまま、日本語・英語の文に混ぜる（「RANK 3」→「Anulus III」、ステージ → Limen、ボス → Culmen）。読み方と意味は、固有名詞にカーソルを当てたときのツールチップで出す。「遊び方」に用語集を置いてもよい。
- 世界の中では Gauntlet を Passus と呼ぶ（Gauntlet は宣伝用の名前）。今のトップの見出し「GAUNTLET」をどちらにするかは未定。
- 失敗を「死」として表現しない。リトライやリタイアの文言は「辿り直す」「入口へ戻る」のような言葉にする。
- 意匠は近世初期（紙・地図・印刷・真鍮の時計）まで。歯車や機械のモチーフは使わない。宗教色の強い記号も使わない。
- Signum の色（黄緑。[placeable.md](placeable.md) の羊毛）は、UI の「選択中」「ON」などに使わない。今の ON の色は青（`@control.on` `#3b6fe0`）で問題ない。クリア済みのバッジ（`@badge.clear.bg` `#2e7d32`）は黄緑の方向へ寄せない。
- ランクの11色が決まったら、名前の色の見本はプロフィールとランキングで出す。

### GUI ではなく世界の中で表すもの

| 設定 | 理由 | どこで表すか |
|---|---|---|
| Signum、相棒が少し先の Signum だけを示すこと | 攻略の最中のことで、画面を開いて見るものではない。合図の色と形が最優先 | ブロック・パーティクル・相棒の動き |
| 崩壊 | 「崩れきる前に辿り切る」緊張感は、景色が崩れることで伝わる | 世界の見た目と音。残り時間を出すとしてもボスバー程度の HUD |
| 空が暮れていく | 土地の雰囲気そのもの | ワールドの空・時刻・ブロックの色（GUI は進行マップの背景で添える程度） |
| 導入（門 → 守り手に迎えられる → 相棒に選ばれる → 最初の Limen） | 説明の画面で語ると、「設定を知らなくても見た目で伝わる」方針に反する | ロビーの門、守り手の NPC、演出。GUI は最初の言語選択だけ |
| ランクアップの演出、本拠地に名が刻まれる | 節目は演出で見せる。名前が実際に刻まれる場所があること自体に意味がある | 本拠地の壁（看板・ディスプレイ）、タイトルと音の演出。GUI は結果を確かめる程度 |
| 名前の色 | ほかのプレイヤーから見えることに意味がある | チャット・TAB・頭上（[player-display.md](player-display.md)） |
| 相棒とのふれあい・付き添い | ロビーや個人空間での触れ合い | 世界の中のやり取り |
| 転移の門 | 門そのものは世界の中にあるべき | 世界の中の門。行き先が多くなったら、行き先選びだけ GUI にする |
| 評議会、歴史、伝承、信仰 | プレイヤーとはほぼ関わらない背景で、物語は閉じない方針 | 出さないか、街並み・本・掲示などでほのめかす |

## 受け取るクリック

| ID | 処理 |
|---|---|
| `dcg:open` | `{"screen":"settings"}` の画面を開く（画面の移動はすべてこれ。`show_dialog` だとサーバーに届かず、プレイヤーごとの状態を出せない） |
| `dcg:close` | 画面を閉じる |
| `dcg:lobby` | 画面を閉じ、`lobby.world` のスポーンへ移動。コース中ならコースを抜けてから。ロビーが無効なら案内のみ |
| `dcg:emote_play` | 画面を閉じ、BetterModel のプレイヤーアニメーション（`model` / `id`）を1回再生。`/bettermodel play` と同じく、再生中はバニラの体を隠す。コース中は使えない。所持の概念はまだなく、全員が全部使える |
| `dcg:emote_page` | 何もしない（全カードが1ページに収まる見本のため） |
| `dcg:settings_set` | 値を設定 → `settings` を送り直す（翻訳先の選択画面からも設定に戻る）。翻訳先の「UI言語に合わせる」は `ui` |
| `dcg:settings_toggle` | ON/OFF を反転 → 送り直し |
| `dcg:settings_step` | 音量を増減（0〜100で止まる） → 送り直し |
| `dcg:settings_reset` | 一般タブの設定（`Settings.ALL` の `menu=true`）を初期値へ → 送り直し |
| それ以外の `dcg:*` | 「準備中」と案内（ランクアップ、お知らせ、コース選択の各操作） |

- 設定を変えるとシステム音（クリック音）を鳴らす。変更後の音量で鳴るので、音量の確認にもなる。本文の文字のクリックではクライアントが音を鳴らさない。
- payload はクライアントから SNBT で届く。`ui/DialogPayload` が最上位の値を文字列にする（数値、真偽値は true/false）。

## エモートと BetterModel

- `softdepend: [BetterModel]`。BetterModel がないときは「使えません」と案内してログに警告を出す。モデル・アニメーションが見つからないときも同じ。
- API は `bettermodel-bukkit-api` / `bettermodel-api`（3.5.1、compileOnly）。呼び出しは `ui/Emotes` にまとめた。

## 実機で分かったこと

- `plain_message` は左右に4pxずつ余白を取る。エディターは `width` を本文幅 + 8 で出す（以前は全行が折り返して崩れた）。
- クリックの判定（26.3 の `ActiveTextCollector`）: 行の中で実際に描かれる文字の範囲（bounds）の外は見ない（空白は範囲に入らない）。範囲の中では、カーソルの下のクリック付きの文字のうち最後のものが選ばれる。エディターは各行の左右の端にほぼ透明な1pxの点を置いて範囲を行の幅いっぱいにする（以前は文字のある所しか反応せず、音量の行は全く反応しなかった）。
- payload に null があるとデータパックの読み込みに失敗してサーバーが起動しない。エディターは null を出さない。

## 未対応（エディター側の機能待ち）

- 差し込み文字（名前・ランク・数値）、リスト（コース・エモート・お知らせ・ランキング）、コースごとの画像。
- コース選択（並べ替え・絞り込み・ページ・検索・お気に入り・開始）：コースIDが仮の値で、一覧の差し込みもまだない。
- リソースパックの配布（URL・SHA-1、読み込み完了を待ってから開く）。
