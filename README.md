# Parkour Gauntlet

コース制作を試すための運営用プラグイン。Paper 26.3 build 166 / Java 25を使用します。
Javaパッケージは `konqasasas.gauntlet`。リプレイ・ランク進行はまだ含みません。設計は [docs/design/](docs/design/README.md) を参照してください。

## 使い方

OPで `/gauntlet kit` を実行すると、制作キットの設置用ブロック（磨かれた安山岩）を受け取れます（1番が空いていれば1番へ）。キットはこのブロック1つで、操作は参加者モードの練習に合わせています。

| 操作（ブロックを持って） | 動作 |
|---|---|
| 通常の設置操作 | 専用の実ブロックを設置。手持ちは64個を維持 |
| F | セーブ。位置・yaw・pitchを保存する（1人1個） |
| Q | 自分の設置用ブロックを片付け、セーブ地点へ移動。視点を戻し、速度・落下距離・スプリント・飛行状態をリセット。アイテム自体は落とさない |
| Shift＋F | Adventure / Creative を切り替える。初期モードが別の場合はCreativeになる |
| Shift＋Q | Qと同じく戻り、さらにコース外トリガーをすべて踏み直せるようにする（セーブより前に踏んだものも） |
| Shift＋左クリック（Adventure） | 設置制限のオン・オフ（`/gauntlet placeable` でも）。オンの間はキットのブロックが光る |

セーブは接地している通常の足場でのみできます。空中・専用設置ブロックの上ではできません。通常の磨かれた安山岩は可能です。
セーブがないときのQでは何も消しません。TPが拒否された場合も足場を残します。
トリガーのアイテム付与で1番がほかのアイテム（メイスなど）に上書きされたときは、1番のそのアイテムでもF・Q・Shift＋Fが効きます（2・3番のアイテムでは効きません）。
以前のキットのアメジスト・スライムボールは何もしません。`/gauntlet kit` を実行し直すと回収されます。
Adventureでは、マグマに触れると自分のセーブ地点へ自動復帰し（Qと同じ）、速度・落下距離・視点を戻して消火します。セーブがある場合は復帰前のマグマダメージも防ぎます。復帰時の音や成功チャットは出しません。セーブがない場合はTPや足場削除をせず、消火のみ行います（直接のマグマダメージは残ります）。通常の火だけによる燃焼や他のゲームモードは変更しません。OP権限に関係なくAdventureのプレイヤーが対象です。
セーブ成功時は `minecraft:entity.experience_orb.pickup`、ゲームモード切替時は `minecraft:block.note_block.pling` を操作した本人に鳴らします。音量・ピッチは1、音カテゴリはプレイヤーです。セーブ地点へ戻るときは鳴らしません。

### キットでの試走（タイマー・コース外トリガー）

コースを作る前の試作で、区間を繰り返し試すための機能です。運営が Adventure でキット（設置用ブロック、または1番のトリガーのアイテム）を持ち、セーブがあり、コース中・ロビーの外にいるときに働きます。1回の試走は、セーブ（F）かセーブ地点へ戻ったとき（Q）に始まります。

- **タイマー**：アクションバーに `4.20s` の形でタイムだけを出します。セーブ地点から動くか、アイテムを使った最初のクライアントtickから数えます（視点だけでは始まりません）。トリガーを踏んでも止まらず、Q・Fで0に戻ります。Creative の間は止まって表示も消えます。
- **コース外トリガー**：コースの範囲外にある鉄の感圧板（重）の上で `/gauntlet trigger` を実行すると登録され、コースのトリガーと同じ画面でアクションを編集できます。踏むと1回の試走につき1回だけ動きます。保存先は `plugins\ParkourGauntlet\triggers.json` です。
- **Qで戻ったとき**：
  - 1〜3番は、セーブした時点の状態に戻ります。キットのブロックかトリガーのアイテムが関わるスロットだけで、Creative で入れた建材などはそのままです。メイスを渡すトリガーの前でセーブすればブロックに、メイスを持ってセーブすればメイスに戻ります。
  - その試走で踏んだトリガーが出した mob だけ消えます。セーブより前に出ていた mob は残ります。
  - セーブの後に踏んだトリガーは、また踏めば動きます。セーブの前に踏んだトリガーは、Shift＋Q で戻ると、また動くようになります。
  - トリガーの水は、セーブした時点の形と残り時間に戻ります（セーブの前に水がなければ消えます）。
- **見分け方**：
  - 設置用ブロックか杖を持っている間、コース外トリガーの感圧板の上に名前（任意）とアクションの要約を浮かべて出します。杖のときは、最後に開いたコースのトリガーにも出します。
  - 一覧は `/gauntlet trigger`（感圧板の上以外で実行）か、コース一覧の「コース外のトリガー」で開きます。近い順に並び、感圧板が壊れたものには ⚠ が付きます。「感圧板がないトリガーを削除」（Shift＋クリック）でまとめて消せます。自動では消しません。
  - トリガーの画面の「名前」で名前を付け（Shift＋右クリックで消す）、「中身をコピー」「貼り付け」で別の感圧板にアクションを写せます。名前はコースのトリガーにも付けられ、コースの版（rev）は上がりません。

専用ブロックはAdventureでも全ブロックを設置対象にできます。専用ブロックの側面にも連続設置できます。
設置距離、プレイヤーとの重なり、設置先の空き、チェスト等の操作ブロックに対するスニーク操作は通常のMinecraftの制約に従います。
通常アイテムとは内部タグで区別し、普通の安山岩やコース用ブロックはリトライで消しません。
`/gauntlet kit` の再実行は既存の専用アイテムを更新し、重複分を整理します。通常アイテムは保持します。

## コース編集（`/course`）

OP（`gauntlet.admin`）で `/course` を実行するとコース一覧のGUIが開きます。編集はすべてGUIで行います。

1. 編集画面の「範囲指定の杖を受け取る」でブリーズロッドを受け取り、左クリックで1点目、右クリックで2点目のブロックを選ぶ。
2. 一覧の「新規作成」でIDをチャットに入力する（英小文字・数字・`_`・`-`、32文字まで）。選択範囲があれば、そのままコース範囲になる。
3. 編集画面で、名前・範囲（杖の選択範囲から）・スタート地点（範囲内で接地した今の位置と向き）・制限時間・状態（下書き／テスト中／完成）を設定する。
4. ダイヤモンドブロックの上に立って「ゴールを登録／解除」を押す（複数登録可。登録済みの上で押すと解除）。
5. 必要なら「初期装備」で1〜3番に入れるアイテムを選ぶ（既定は1番に設置用ブロック。1番は必須）。以前の4番の設定は読み込み時に捨てられます。
6. 鉄の感圧板（重量感圧板・重）の上に立って「足元のトリガーを編集」を押し、アクションを追加する。
7. 「ルート（到達率）」で、スタートからゴールまで通るべき道に沿って点を置く（左クリック：今の位置を追加、右クリック：最後の点を削除、Shift＋右クリック：全削除）。到達率（%）の計算に使います。
8. 必要なら「設置可能箇所」でマーカー（黄緑の羊毛）を受け取り、ブロックを置いてよいマスに置く。ブロックは置かれず、そのマスが登録されます（登録済みのマスにもう一度置くと解除、ボタンのShift＋右クリックで全削除）。登録したマスがあるコースでは、本番・練習中にそれ以外の場所へブロックを置くと失敗になります（記録の理由は `PLACE`）。1つも登録しなければ、今までどおりどこにでも置けます。

杖を手に持っている間だけ、選択範囲（黄）・最後に開いたコースの範囲（水色）・スタート地点（黄緑の柱）・ゴール（白の枠）・トリガー（橙の枠）・ルート（赤紫の線）をパーティクルで表示します。設置可能箇所は小さい黄緑の羊毛（BlockDisplay）で、杖かマーカーを持った運営と、そのコースを遊んでいるプレイヤーにだけ見えます。

範囲・スタート・ゴール・制限時間・初期装備・トリガー・失敗条件・ルート・設置可能箇所を変えると、コースの**版（rev）**が1つ上がります（編集画面の本の説明に表示）。記録・自己ベスト・挑戦回数は版ごとに分かれます。名前・状態の変更では上がりません。
コースは `plugins\ParkourGauntlet\courses\<id>.json` に1ファイルずつ保存します。削除したコースは `courses\deleted\` に退避します。
読み込めないファイルは起動ログに出してスキップし、上書きしません（同じIDでの新規作成も拒否します）。

### アイテムテンプレート

一覧・編集画面の「アイテムテンプレート」で管理し、`plugins\ParkourGauntlet\templates.json` に保存します（全コース共通）。
「手持ちのアイテムを登録」でメインハンドのアイテムを個数・データごと登録するか、メイス・ウィンドチャージ・エリトラ等をワンクリックで追加します。
クリックで耐久値無限の切り替え、右クリックで名前変更、Shift＋右クリックで削除。メイスのテンプレートは、渡すときにウィンドバーストⅠ〜Ⅲを選びます。
渡したアイテムには内部タグ（テンプレートとレベル）が付き、「持っているか」はこのタグの完全一致で判定します。

### トリガーとアクション

登録した鉄の感圧板を踏むと、1回の挑戦につき1回だけ、アクションを上から順に実行します（1つのトリガーに18個まで）。

| アクション | 内容 |
|---|---|
| アイテム付与 | 完全に同じもの（テンプレート＋レベル）を持っていなければ渡す。渡す場所は「1番を上書き」「2・3番」「2〜3番の空き」（以前の「4番」は「2〜3番の空き」として扱う） |
| アイテム削除 | 指定テンプレートを消す。メイスは全レベルか指定レベル |
| mobスポーン | `minecraft:strider -84 -56 -37 {Age:0,Silent:1b}` のような summon の内容をチャットで入力。座標があればその位置、なければ今の位置。`Tags` は使用不可（追跡用に自動で付ける） |
| サウンド | 一覧から選ぶかIDを入力。音量・音程は編集画面で調整、本人にだけ鳴らす（本人の「コースの演出音」の音量設定が掛かる） |
| 水 | 登録したマス（64マスまで）に水源を置き、決めた時間（0.05〜300秒。既定3秒）が過ぎたら水源だけ消す（流れていた水はふつうの水と同じように引いていく）。水は流れるが、空気のマスにだけ広がる（物を壊さず、元からある水にも入らない） |

スポーンしたmobは、失敗・リトライ・終了時に消します。ワールドには保存されず、クラッシュ後に残ったものは読み込み時に削除します。

水のアクションは、追加すると水のマーカー（青い羊毛）を受け取ります。マーカーを置いたマスが、最後に開いた水のアクションに登録されます（もう一度置くと解除。ブロックは置かれない）。マーカーを持っている間は、登録したマスが青い枠で見えます。出ている時間はクリックで±0.5秒、Shift＋クリックで秒を入力します。
- 出した水は、踏んだ人のものとして1マスずつ記録します（置いた水源と、そこから流れて広がったマス）。失敗・リトライ・コースを抜けたとき・ログアウトで、記録したマスのうち今も水のマスだけを、その場で空気に戻します。ほかの水やブロックには触りません。
- 時間切れでは、記録したマスの水源だけを消します（2つの水源の間にできた水源も含む）。流れていた水が引ききるまで記録は残すので、引いている途中のリセットでもその場で消えます。30秒たっても残っている水は、その場で消します。
- 記録は `plugins\ParkourGauntlet\water.json` にも書き（最大1秒遅れ）、クラッシュで残った水は次の起動で消します。
- 水の中に設置用ブロックを置くと、そのマスは記録から外れ、ブロックを片付けると空気に戻ります。
- 同じコースを何人かで遊ぶときは、レーンを分けると水も足場も干渉しません（下の「レーン」）。同じレーンを共有する遊び方はありません。
mobのSNBTはMinecraftのバージョンで書式が変わることがあります。バージョン更新時はmobのアクションを確認してください。

## 参加者モード（本番・練習）

編集画面の「参加者モードで遊ぶ」（左クリック：本番、右クリック：練習）、または `/course play <ID>`・`/course practice <ID>` で開始し、`/course leave` で終了します。別のコースを始めると今のコースは自動で抜けます。運営は全コース、それ以外は「完成」のコースだけ遊べます（進行状況の仕組みができるまでは「完成」＝開放済み）。

- 開始時に位置・ゲームモード・所持品を `plugins\ParkourGauntlet\participants.json` に保存してから、スタートへ移動・Adventure・初期装備の状態にします。終了・ログアウト時に元へ戻します。サーバーが落ちた場合も次の参加時に戻します。
- スタート地点（練習ではセーブ地点）から位置が動くか、アイテムを使った（右クリック・設置・スイング）最初のクライアントtickを0として計測します。視点だけでは始まりません。
- 計測は `ClientTickEndEvent`（Paper）の受信数です。1秒以上届かない場合は「計測不能」と表示し、その挑戦は INVALID として記録します（自己ベストには使いません）。制限時間はクライアントtickで判定し、通知が止まった場合のためにサーバー時計でも制限時間の1.5倍で打ち切ります。
- 失敗条件：マグマ・範囲外（コースごとにオン／オフ）、死亡、時間切れ（本番のみ）、設置可能箇所以外へのブロック設置（登録があるコースのみ）。失敗すると本番はスタート、練習はセーブ地点（なければスタート）に戻ります。
- 戻るときは、設置用ブロックの足場・mobを片付け、装備・エフェクト・トリガーの発火状態を戻します。
- インベントリ操作・持ち替え・アイテムを拾うことはできません。

| スロット・キー | 本番 | 練習 |
|---|---|---|
| 1〜3 | コースのアイテム | 同じ |
| 1番を持ってQ | スタートへ（計測中ならリタイア。ゴール後はリトライ） | セーブ地点へ（なければスタート） |
| F | — | セーブ（地面の上のみ。1つ前のセーブは `/course undosave` で戻せる） |
| 5 | 練習に切り替え（砂糖。スタートから） | 本番に切り替え（レッドストーン） |
| 6 | — | 飛行のオン／オフ（羽。オンで光る。実際に飛んだ区間のタイムは無効） |
| 8 | プレイヤー表示の切り替え | 同じ |
| 4・7・9 | 空き（9番は今後メニューを置く予定） | 同じ |

- 情報はすべてアクションバーに出し、タイトル表示は使いません。部品は薄灰色の `|` で区切ります（例：`12.35s / 30s | 63.4% | [Q] リトライ`、練習は `練習 | 区間 4.20s | 63.4% | [Q] セーブ地点へ | [F] セーブ`）。Q・Fはプレイヤーの実際のキー設定で表示します。1番のアイテムの説明文にも書きます。
- ルートが登録されたコースでは到達率（%）を出します。本番はその挑戦で一番進んだ位置、練習は今の位置の%です。壁越しに先のルートへ近づいても%が飛ばないよう、今の位置に近い区間だけで判定します。
- 失敗しても理由などは表示せず、音だけ鳴らして戻ります。セーブの結果はチャットに出します。飛行・プレイヤー表示の切り替えは通知しません（アイテムの見た目で分かるため）。
- アイテムは入れ替えるスロットだけを直接書き換えます（`/item replace` と同じで、拾ったときのような弾む動きが出ない）。
- 時間は日本語でも `12.35s` の形です。
- 本番でゴールするとチャットにタイム・tick数・自己ベストとの差を出し、その場で待機します。
- 練習のセーブは位置・持ち物・エフェクト・トリガーの発火状態・その時点までの足場・mob（状態ごと）・トリガーの水（流れた形と残り時間ごと）を保存します。ロードするとセーブ後に置いた足場だけ消えます。練習では時間切れになりません。
- 練習の区間タイムは、ロード（またはスタート）後に動いてから、次のトリガーかゴールまでです。記録には残りません。
- コースにレーンがあるときは、空いているレーンに入ります（チャットに「レーン 2／5 で遊びます」）。全レーンが使用中なら順番待ちになり、空いたら自動で始まります。待っている間はアクションバーに何番目かを出し、`/course leave` でやめられます。
- コース中はほかのプレイヤー本人は見えず、同じ時代（時代に入っていないコースは同じコース）のほかのレーンの人が、自分のレーンの同じ場所にゴーストとして見えます（下の「ゴースト」）。8番でプレイヤー表示を消すと、ゴーストも消えます。
- 本番の全試行をデータベースの `runs` に記録します（コース・版・プレイヤー・結果 CLEAR/FAIL/RETIRE/QUIT/INVALID・失敗理由・tick・実時間・到達率・開始／終了時刻・終了位置・レーン番号〔1から〕）。

- **コース外の設置可能箇所**：どのコースの範囲（レーンの写しも含む）でもない場所で設置可能箇所マーカー（黄緑の羊毛）を置くと、キットの試走用の設置可能箇所になります（もう一度置くと解除）。マーカーは `/gauntlet marker`（またはコースの編集画面の「設置可能箇所」）で受け取れます。保存先は `plugins\ParkourGauntlet\placeable.json` です。キットのブロックかマーカーを持っている間、48ブロック以内のマスが黄緑の小さな立方体で見えます。設置制限がオンのとき（Adventure・セーブあり）、マス以外に置こうとすると置けずにセーブ地点へ戻ります（コースの失敗と同じく音だけ）。Creative では制限しません。コースの編集画面の「設置可能箇所」を Shift＋左クリックすると、そのコースの範囲の中にあるコース外のマスをコースへ移します。

トリガーが動くのは、感圧板が実際に押されたときです（バニラと同じ判定：板の縁から1/16内側・高さ1/4の範囲に足が触れたとき）。感圧板のあるマスに入っただけでは動きません。trigger の mob は、コンソールに「Summoned new …」を出さずに呼び出します。

## 時代

前につながった複数のコース（1-1、1-2、…、1-ボス）のまとまりです。コード上は era、保存先は `plugins\ParkourGauntlet\eras.json` です。

- コース一覧の「時代」で作ります。時代は名前・範囲（全コースを含む箱。杖で選ぶ）・コースの順番・レーンを持ちます。1つのコースが入れる時代は1つだけです。自分のレーンを持つコースは、先にそのレーンを消してから入れます。
- **進み方**：ゴールしたあと、同じレーンで別のコースのスタート地点のブロックに乗ると、そのコースに切り替わります（初期装備に入れ替え、動いたら計測開始）。前のコースに戻るのも同じです。ゴール前に乗っても切り替わりません。
- **ゴール後**：範囲外・マグマでは失敗しません。時代の範囲（そのレーンの箱）から出るかマグマに入ると、ゴールしたブロックの上に戻ります。死んだときもゴールで復活します。
- **到達**：スタートのブロックに乗って切り替わったとき（とそのコースに入ったとき）、そのコースを「到達」としてデータベースの `reached` に記録します（初めての日時だけ）。ランクとは別です。
- **どこから始めるか**：`/course era <時代のID>` で、到達したコース（1番目は誰でも）を選んで始めます（左クリック：本番、右クリック：練習）。`/course era <時代> <コース>` でも始められます。`/course play` で時代のコースを始めるときも同じ条件です。運営は全部始められます。
- **レーン**：レーンは時代が持ち、時代の範囲全体を写します。時代の中を進む間はレーンが変わらず、ロビー・`/course leave`・ログアウトで返します。
- **ログアウトからの再開**：時代の途中でログアウトすると（サーバーの停止も同じ）、次のログインで、そのコースのスタートに空いているレーンで入ります。全レーンが使用中なら `config.yml` の `eras.waiting-spot`（空ならロビーのスポーン）で順番待ちになります。練習のセーブ地点は残りません。回線切れでも元のレーンは取っておきません。
- 時代に入っていないコースは、そのコースだけで時代のように扱います（レーンはコースが持つ）。

### ランク

来たばかりの人はランク0（輪なし）で、時代のボスを倒すとランクが上がります（1〜11、Anulus）。ランクは `gauntlet.db` の `ranks` に残り、下がりません。

- 時代の編集画面で、**ボス**（時代の中のコース）と**撃破で上がるランク**、**入るのに必要なランク**を決めます。時代Iはボスでランク1・必要0、時代IIはボスでランク2・必要1、…です。
- ボスのコースを**本番で**クリアしたとき（計測不能は除く）だけ上がります。練習では上がりません。ゴールの判定はほかのコースと同じです。
- 上がった瞬間は今はチャットの一行と音だけです（`play/RankUps.java`。演出はここに入れる）。
- 必要なランクに届いていない人は、その時代のコースを始められません（運営は除く）。
- 名前の色（チャット・TAB・頭上・スコアボード）はランクで決まります。ランク0の札と色は `display.yml` の `ranks.zero-badge`（既定「—」）と `ranks.zero-style`（既定は目立たない灰色）です。
- 運営は `/gauntlet rank [プレイヤー] [0〜11]` で確認・設定できます（テスト用。下げることもできる）。

## レーン

同じコースを何人かで同時に遊べるように、写しを並べておく仕組みです。水・足場・mob はレーンごとなので干渉しません。レーンは時代が持ちます。時代に入っていないコースは自分で持ちます。

- コースの設定（範囲・スタート・ゴール・トリガー・水・mob の位置・設置可能箇所・ルート）は1つだけで、1レーン目の座標で持ちます。2レーン目以降は、それをレーンのずらし量だけ動かして使います。記録と版（rev）もレーンで分かれません。
- 時代の編集画面の「レーン」（時代に入っていないコースはコースの編集画面の「レーン」）で一覧を開きます。各レーンの状態（空き・使用中・同期待ち・同期中）と使っている人が見え、クリックでそのレーンのスタートへ移動します。
- **追加**：数と間隔をチャットで入力します。`4 x 200` は最後のレーンから x 方向に200ずつ4本、`3 0 0 -150` はずらし量を直接指定です。レーンどうし・ほかのコースと重なる場合や、ワールドの高さからはみ出す場合は追加しません。1レーン目を含めて64本までです。追加したレーンには1レーン目のブロックを写します。
- **同期**：「1レーン目から同期」で、1レーン目のブロックをほかの全レーンに写します。1tickに最大32768マスを見て4096マスまで書き換えます。使用中のレーンは、その人が抜けてから写します。写し終わるまで、そのレーンには誰も入りません。1レーン目にある誰かの足場とトリガーの水は、元のブロック（空気）として写します。エンティティ（額縁・防具立てなど）は写しません。未完了の同期は `plugins\ParkourGauntlet\lanes.json` に残り、再起動後に続けます。
- **編集は1レーン目だけ**：2レーン目以降では、ブロックの設置・破壊・バケツができません（そのレーンで遊んでいる本人の足場だけは置けます）。スタート・ゴール・トリガー・水のマス・mob の位置・ルート・設置可能箇所も、1レーン目でしか登録できません。範囲を変えたら同期し直してください。
- **削除**：「最後のレーンを削除」（Shift＋クリック）。使用中のレーンは消せません。ブロックはその場に残ります。
- 杖を持つと、近くのほかのレーンの範囲も灰色の枠で出します。感圧板の上の文字と設置可能箇所の表示も、各レーンの位置に出ます。
- トリガーの「貼り付け」は、左クリックでそのまま、右クリックで感圧板の位置の差だけ mob の位置と水のマスをずらして貼ります（同じ形の仕掛けを別の場所に作るとき）。

### ゴースト

同じ時代のほかのレーンの人を（遊んでいるコースが違っても）、自分のレーンの同じ位置に Mannequin（プレイヤーのスキンの人形）として出します。見る人ごとに別のエンティティで、毎tick位置・向き・しゃがみ・手に持った物・腕振りを写します。保存はしません。

- Display エンティティで体を組み立てる方式（BetterModel）は、大勢が同じ場所に集まると重かったため使っていません。
- Mannequin はプレイヤーと同じくクリックを受け止めます（チームでは変えられません。26.3 のクライアントで確認）。手前にいると、その先のブロックに設置できません。そこで、目から `ghosts.hide-within`（5ブロック）以内に入ったゴーストは、その人にだけ隠します。
- 押し合いと名札は、サイドバーのチーム（衝突なし・名札なし）で消しています。
- 設定は `config.yml` の `ghosts`：`near`（この距離以内の人だけ。64）、`max`（近い順に何人まで。0なら上限なし）、`hide-within`。変えたら再起動します。
- ゴーストが鉄の感圧板の上に重なると、感圧板が押された状態になる可能性があります（未確認。コースのトリガーはプレイヤーの位置で判定するので、トリガーは動きません）。

## 自動生成の試作（モジュール）

`/module` でモジュール（自動生成の部品）の一覧を開き、作成・編集します（編集画面はコースと同じ。`/course` の一覧には出ません）。範囲・スタート（入口）・ゴール（出口。複数ならいちばん +Z 側）・トリガー・ルート・設置可能箇所はコースのものをそのまま使い、足すのは難易度（1〜5）、モジュール時間（秒）、初期装備1〜3番を配る数（0 は無制限で、足場は64個に補充）です。回転はしないので、+Z に進む形で作ります。

- `/module generate <プロファイル> [シード]` で、試験場所にモジュールをつないだコース `gen_<プロファイル>` を作ります。同じシードなら同じ並びです。遊ぶのは `/module play <プロファイル>`（練習は `/module practice <プロファイル>`）で、生成したコースは `/course` の一覧には出ません。生成のたびに、それまでに生成したコース（どのプロファイルでも）は空気で埋めて消します。`/module remove <プロファイル>` でも消せます。各モジュールは、シードで決まる半分の確率で左右反転して置きます（ブロックの向きも反転。1つの登録で2通り）。モジュールの範囲の中のガラスブロック（範囲の目印）は写しません。モジュールの一覧には難易度ごとの数（生成に使える数も）が出ます（`/module settings` でも）。モジュールの一覧は名前順（数字は数の大きさの順：m1-2 は m1-10 より前）で、45個ずつのページに分かれます。
- 設定（`config.yml` の `generator`）は、モジュール一覧の「生成の設定」（または `/module menu`）のチェストGUIで変えられます（試験場所・難しいモジュールの続き方・つなぎ目・プロファイルの個数／分布／でこぼこ／難易度帯の決まり、生成・遊ぶ・練習も）。コマンドでも変えられ、次の生成から使います：`/module place`（足元のブロックを試験場所に）、`/module set <hard-from|max-hard-streak|joint|joint-length|joint-block> <値>`、`/module profile <名前> <個数> <難易度1〜5の割合（5つ）> [でこぼこ]`（例：`/module profile test 8 1 3 3 2 1 1.5`）、`/module profile remove <名前>`、`/module settings`（今の設定）。
- 難易度はプロファイルの分布（`distribution`：難易度1〜5の割合）から個数ぶん引き、易しい順に並べてから、でこぼこ（`bumpiness`）の強さだけ順番を入れ替えます（でこぼこした山登り。0なら易しい順のまま）。プロファイルの難易度帯の決まり（`bands`：`"4-5:1-2"` なら難易度4〜5を1〜2個）があれば、引いた結果が決まりに合うまで、足りない帯の中から／多すぎる帯の外から分布の割合で引き直します（どうやっても満たせないときは生成せずに知らせます）。並べた難易度ごとに、近い難易度のモジュールから選びます。同じモジュールは1回の生成で1度だけ（左右反転したものも含む）、`hard-from` 以上のモジュールは `max-hard-streak` 個まで続けます。
- 前のモジュールのゴールの位置に次のスタートのブロックが来るよう、高さも含めて自動でずらします（`joint: platform` なら間に `joint-length` の平らな足場）。ワールドの高さからはみ出す・前のブロックと重なる場合は別のモジュールを試し、置けなければ何個目で何が理由かを出します（ワールドは変えません）。
- 遊び方：モジュールに入るとその配る物に入れ替わり、モジュール時間が残り時間に足されます（コースの中で持ち越し）。残り時間が切れると失敗、落ちたらコースの最初へ戻ります。到達率はモジュールのルートをつないだもの。
- 設置可能箇所は全モジュールのものを合わせます（どれかに登録があると、登録のないモジュールでも登録マス以外に置けません）。

## 順位表

`/ranking <コース>` で、そのコースの今の版の本番クリアの上位10人と自分の順位を出します（1人1行でベスト。同じタイムは先に出した人が上。INVALID は入りません）。`/ranking rank <数>` は、そのランクに早く届いた順です。メニューからは `dcg:ranking`（`{course:"<ID>"}` か `{rank:"<数>"}`）で開けます。行の見た目は装飾の「順位の行」の標準版で、名前はランクの色です。

運営：`runs <人> <コース>`（クリアの一覧と記録ID）、`void <人> <コース> [理由]`／`void-run <記録ID> [理由]`（順位表から外す。記録は消さず、誰が・いつ・なぜを残す。ランクは下がらない）、`restore`／`restore-run`（戻す）、`carry <コース>`（今の版に前の版の記録を引き継ぐ）／`uncarry`。

## リプレイ

本番の挑戦は時計が動いた時点から毎tick記録し（位置・視点・しゃがみ・ダッシュ・手の物・腕振り、コースの中で変わったブロック、mob や落ちる砂などの物体）、クリアしたときだけ `plugins\ParkourGauntlet\replays\<記録ID>.replay` に保存します。プレイヤー×コース×版ごとにベストと直近の数件（`config.yml` の `replays.recent`、既定3）を残し、全体の容量（`replays.max-mb`）を超えたら、誰のベストでもない古いものから消します。

運営は `/replay list [人]` で一覧、`/replay play <記録ID>` で一人称で見られます。ブロックや物体は見ている人にだけ見えます。見ている人は見えない台に乗って動くので、移動はクライアントが補完して滑らかに見えます。操作はホットバーのアイテムの右クリックで、真ん中（5番）の一時停止／再開をはさんで 4 1tick戻る、6 1tick進む、7 速さ（0.5／1／2倍を順に）です。1番は記録した人が持っていた物、9番で終わります（元の位置と持ち物に戻る）。アイテムは `config.yml` の `replays.keys` に頭のテクスチャの値を書くと頭になります。

## 装飾（共通のデータ）

見た目だけの物の「持っている物」「使っている物」「購入の記録」を `gauntlet.db` に持ちます。一覧は `cosmetics.yml`（枠・商品・まとめ売り。枠はファイルで足せる。名前の色・ランク・称号・トロフィーは枠にできない）で、`/cosmetic reload` で読み直します。各枠に無料の標準版があり、何も選んでいなければそれを使います。入手方法は「最初から／報酬のみ／購入」で、報酬のみの物は購入として渡せません。購入の記録は買った人と受け取る人を分けて持ち、取り消しても残ります。中身（演出）、選ぶ画面、決済のつなぎ込みはまだありません。

運営（テスト用）：`/cosmetic catalog`、`list <人>`、`grant <人> <商品かまとめ売り> [reward|start|purchase]`、`revoke <人> <商品>`、`equip <人> <商品>`、`purchases <人>`。

## チャット翻訳

自由チャットを閲覧者ごとに翻訳します（個人メッセージ等は対象外）。

- 自動翻訳ON：翻訳文を `[訳]` 付きで表示し、ホバーで原文と元の言語を表示します。
- 自動翻訳OFF（初期値）：発言者のクライアントの言語と自分の翻訳先が違うとき、原文の後ろに `[翻訳]` ボタンが付きます。押した人にだけ翻訳文を表示します。
- 翻訳先の初期値は表示言語（UI言語）と同じです。設定は個人設定に保存され、`/settings` または次のコマンドで変更できます。

```
/translate              現在の設定を表示（運営には今日の送信文字数も表示）
/translate on|off       自動翻訳の切り替え
/translate lang <言語>  翻訳先（ja, en, ko, zh-CN, zh-TW, es, pt, fr, de, ru, it, th, vi, id）、ui で表示言語に戻す
```

翻訳エンジンは `plugins\ParkourGauntlet\config.yml` の `translation.engine` で切り替えます（変更後は再起動）。

| engine | 内容 |
|---|---|
| `mymemory`（既定） | MyMemory。キー不要。1日5,000文字、`mymemory.email` に連絡用メールを書くと50,000文字 |
| `libretranslate` | 自前のLibreTranslateサーバー（`libretranslate.url`、必要なら `api-key`） |
| `none` | 翻訳しない |

- 同じ言語の文や短すぎる文（かなを含む文を日本語へ、など）はAPIを呼ばず、同じ文はキャッシュから返して無料枠を節約します。
- 2.5秒（`timeout-ms`）以内に返らなければ原文と `[翻訳]` ボタンで表示します。無料枠を使い切ったらその日（UTC）は翻訳を止めます。
- 翻訳文はサーバーが書き換えた表示のため、受け手のクライアントで「改変されたメッセージ」の印が付く場合があります。サーバーログには原文が残ります。

## 多言語表示・個人設定

画面の文言は `src\main\resources\lang\ja.yml`・`en.yml`（MiniMessage形式）にあります。表示言語は個人設定 `ui_lang`（自動＝クライアントが日本語なら日本語、それ以外は英語）です。
`plugins\ParkourGauntlet\lang\<言語>.yml` に同じキーを書くと上書きでき、`/gauntlet reload lang` で読み込み直します。運営向けの画面（`editor.*`）は当面日本語だけです。

個人設定は `/menu` の設定画面か、次のコマンドで変更します。設定の一覧は `data/Settings.java` にあり、画面はこの定義から組み立てる想定です。

```
/settings                 一覧を表示
/settings <キー> <値>     変更（例：/settings sound.system 50）
/lang ja|en|auto          表示言語
```

| キー | 内容 | 値 |
|---|---|---|
| `ui_lang` | 表示言語 | auto / ja / en |
| `translate_lang` | 翻訳先 | ui（表示言語と同じ）/ 14言語 |
| `translate_auto` | 自動翻訳 | true / false |
| `sound.system` | システム音の音量 | 0〜100（10刻み） |
| `sound.course` | コースの演出音の音量 | 0〜100（10刻み） |
| `players.visible` | プレイヤー表示（8番のアイテムで切り替え） | — |

## メニュー（Dialog）

`/menu` でメニュー画面を開きます。画面はこのリポジトリの Dialog エディター（[dialog-editor/](dialog-editor/README.md)。本番では `https://catenaonline.net/dialog/`）で作ります。本番に出したメニューは `config\menu\` にあり、手元のサーバーへは `deploy.ps1 -Menu -Local` で `plugins\ParkourGauntlet\menu\` とデータパックに入ります。本番では、メニューとエモート（BetterModel）のリソースパックを参加時にプラグインが送ります（`config.yml` の `resource-packs`）。手元の試験用サーバーでは送らないので、`config\menu\resourcepack.zip` をクライアントに入れて使います。手順は [docs/VPS_SERVER.md](docs/VPS_SERVER.md) の「メニュー」を参照してください。プラグインが雛形からプレイヤーごとの画面を組み立てて送るので、設定画面には今の値が表示されます。雛形を差し替えたら `/gauntlet reload menu` で読み直します。
今つながっているのは「画面の移動」「✕で閉じる」「ロビーへ戻る」「エモート（BetterModel）」「設定」です。それ以外のボタンは「準備中」と出ます。詳細は [docs/design/menu-dialog.md](docs/design/menu-dialog.md)。

## 表示（TAB・スコアボード・名前）

- 名前は `[ 1 ] [ADMIN] 名前` の形で、チャット・TABに出します（頭上は `[ 1 ] 名前`）。名前の色はランク色です。**ランクの仕組みはまだないため全員ランク1、色も仮です。** `[ADMIN]` は権限 `gauntlet.display.admin`（既定OP）で付きます。
- 頭上の名前はプレイヤーに乗せたTextDisplayで表示し、バニラの名前は隠します。コース中は出しません。乗せたままだとワールドをまたぐテレポートができないため、コマンド実行時・ポータル・プラグインのテレポートの前に外し、0.5秒以内に付け直します。
- TAB：ヘッダーにロゴ、フッターに自分のPingと `Tips`（言語によらずこの表記。20秒ごとに切り替え）。並びは ADMIN → ランク → 名前。
- スコアボード：`Player:`・`Rank:`・`Playtime:`（見出しは金色）とサーバーIP。コース中は `Course:`（コース名）・`Best:`（自己最高の到達率。クリア済みなら `Clear ✓ タイム`、どちらもなければ `—`）・`Attempts:` を追加します。
- サーバー名・接続先は `config.yml` の `server.name`（既定 `Catena Online`）・`server.address`（既定 `mc.catenaonline.net`）。
- 名前の書式・11ランクの色・チャットの書式・TABのヘッダーとPingの色・スコアボードの行・サーバー一覧の説明（motd、空なら server.properties のまま）は `display.yml`（同梱の既定値を `plugins\ParkourGauntlet\display.yml` で項目ごとに上書き）で決まり、`/gauntlet reload display` で再起動せずに反映されます。Webエディター（`web/editor/index.html`）でプレビューしながら編集できます。手順は [docs/VPS_SERVER.md](docs/VPS_SERVER.md) の「表示設定」を参照してください。
- 透明化したプレイヤーは完全に見えません（チームの「味方の透明を見られる」をオフ）。防具・持ち物も、ほかの人には毎tick「なし」と送って隠し、頭上の名前も消します。TABには残ります。
- プレイヤー同士は干渉しません：押し合いなし（チームの衝突ルール）、攻撃・ノックバック（メイス・ウィンドチャージ・爆発を含む）なし、ほかのプレイヤーの飛び道具はすり抜ける、ポーション・釣り竿も効かない。ほかのプレイヤーが立っている場所にもブロックを置けます（自分の体の中や、mob・乗り物がいる場所は不可）。mobとプレイヤーの間は通常どおりです。
- 8番の「プレイヤー表示」で非表示にすると、ほかのプレイヤーはTABからも消えます（Paperの仕様）。

### HotSwap（再起動なしでコード変更を反映）

開発中は JetBrains Runtime（JBR）でサーバーを起動すると、変更したクラスを稼働中のサーバーへ直接反映できます。プラグインの unload/load は行いません。

```powershell
# 初回のみ: JBR 25 を run\jbr-25 に取得（SHA-512検証あり）
powershell -NoProfile -ExecutionPolicy Bypass -File .\prepare-jbr.ps1
# いつも通り配置してから HotSwap モードで起動
powershell -NoProfile -ExecutionPolicy Bypass -File .\prepare-server.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-server.ps1 -Hotswap
# コードを変更したら別ウィンドウで（コンパイル→変更クラスだけ反映）
powershell -NoProfile -ExecutionPolicy Bypass -File .\hotswap.ps1
```

- メソッド本体の変更に加え、フィールド・メソッドの追加削除、新しいクラスの追加にも対応します。
- `onEnable` で一度だけ行う処理（コマンド・リスナー登録、config 読み込み、スケジュール済みタスク）は再実行されません。`plugin.yml` やリソースの変更も対象外です。これらは `prepare-server.ps1` で配置し直して再起動してください。
- 反映状況は `build\hotswap` に記録されます。配置済み JAR が更新されると自動でリセットされます。

停止はサーバーコンソールの `stop`。この開発環境では次のローカル補助ツールでも停止できます。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\verify-server.ps1 -Action stop
```

## 保存と制約

CPと設置履歴は `run\paper-26.3\plugins\ParkourGauntlet\state.json` に保存します。
プレイヤーのプロフィール（初参加・最終ログイン・プレイ時間）・個人設定・案内の表示回数・本番の記録は `plugins\ParkourGauntlet\gauntlet.db`（SQLite）に保存します。SQLiteのドライバはPaperが起動時にMaven Centralから取得します（`plugin.yml` の `libraries`）。
以前の `records.jsonl`・`chat-prefs.json` は初回起動時にデータベースへ取り込み、`.migrated` を付けた名前で残します（旧記録の版は0、到達率なし）。
ログアウト・サーバー停止時に専用足場を片付け、起動時に残った履歴も回収します。CPは維持します。
設置前のBlockDataを記録し、リトライ時に戻します。記録後に別種類のブロックへ編集した場所は上書きしません。
同じ種類・同じBlockDataへの再編集は履歴と区別できません。専用足場を永久コースに転用する場合は、先にリトライで片付けてから普通のブロックで設置してください。

現段階では**実ワールドの足場**を使います。同じコースの同時プレイはレーンで分けます。
ピストン・爆発等で足場を移動／消去する運用は未対応です。CPの保存後に周囲の地形を変更した場合の安全なTP先の再選定も未実装です。
設置履歴はブロックごとに同期保存します。大人数・高速連続設置の負荷試験は今後の対象です。

権限は `gauntlet.admin`（既定OP）。他の保護プラグインの設置制限を強制解除する処理はありません。
サーバー全体の移動検証・飛行制限を緩める設定変更はしていません。

検証結果は [docs/VALIDATION.md](docs/VALIDATION.md)、実機テストは [docs/TESTING.md](docs/TESTING.md) を参照してください。

## Gitで保護する範囲

ソース、テスト、Gradleラッパー／依存ロック、補助スクリプト、手順書を管理します。
ワールド・サーバー設定・OP／ホワイトリスト・CPデータ等の `run/`、生成JAR・ログ等の `build/`、Gradleキャッシュは対象外です。
既存のワールドはディスクに保持しますが、Gitからは復元できません。
新しいチェックアウトでも旧試作を参照せず、`prepare-server.ps1` で指定ビルドのPaperを取得できます。Minecraft EULAへの同意と運用設定は別途必要です。

変更を保存する場合:

```powershell
git status
git diff
# 変更したファイルを明示して追加する
git add src/main/java/konqasasas/gauntlet/ParkourGauntletPlugin.java
git commit -m "変更内容"
```

ローカルGitの履歴は同じPC上にあります。PCの故障にも備えるには、後で別ディスクへのバックアップか非公開リモートへの保存が必要です。
