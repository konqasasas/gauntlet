# Parkour Gauntlet

コース制作を試すための運営用プラグイン。Paper 26.3 build 166 / Java 25を使用します。
Javaパッケージは `konqasasas.gauntlet`。ゴースト・リプレイ・レーン・ランク進行はまだ含みません。設計は [docs/design/](docs/design/README.md) を参照してください。

## 使い方

OPで `/gauntlet kit` を実行すると、次の専用アイテムを受け取れます。

| アイテム | 操作 | 動作 |
|---|---|---|
| アメジストのかけら | Q（ドロップ） | 自分のCPを1個保存。位置・yaw・pitchを保存し、アイテム自体は落とさない |
| アメジストのかけら | 右クリック | 自分の設置用ブロックを片付け、CPへ移動。視点を戻し、速度・落下距離・スプリント・飛行状態をリセット |
| スライムボール | 右クリック | Adventure / Creative を切り替える。初期モードが別の場合はCreativeになる |
| 磨かれた安山岩 | 通常の設置操作 | 専用の実ブロックを設置。手持ちは64個を維持 |

CPは接地している通常の足場でのみ設定できます。空中・専用設置ブロックの上では設定できません。通常の磨かれた安山岩は設定可能です。
CP未設定の右クリックでは何も消しません。TPが拒否された場合も足場を残します。
Adventureでは、マグマに触れると自分のCPへ自動復帰し、自分の専用足場を片付け、速度・落下距離・視点を戻して消火します。CP設定済みの場合は復帰前のマグマダメージも防ぎます。復帰時の音や成功チャットは出しません。CP未設定の場合はTPや足場削除をせず、消火のみ行います（直接のマグマダメージは残ります）。通常の火だけによる燃焼や他のゲームモードは変更しません。OP権限に関係なくAdventureのプレイヤーが対象です。
CP設定成功時は `minecraft:entity.experience_orb.pickup`、ゲームモード切替時は `minecraft:block.note_block.pling` を操作した本人に鳴らします。音量・ピッチは1、音カテゴリはプレイヤーです。CP復帰時は鳴らしません。

専用ブロックはAdventureでも全ブロックを設置対象にできます。専用ブロックの側面にも連続設置できます。
設置距離、プレイヤーとの重なり、設置先の空き、チェスト等の操作ブロックに対するスニーク操作は通常のMinecraftの制約に従います。
通常アイテムとは内部タグで区別し、普通の安山岩やコース用ブロックはリトライで消しません。
`/gauntlet kit` の再実行は既存の専用アイテムを更新し、重複分を整理します。通常アイテムは保持します。

## コース編集（`/course`）

OP（`gauntlet.admin`）で `/course` を実行するとコース一覧のGUIが開きます。編集はすべてGUIで行います。

1. 編集画面の「範囲指定の杖を受け取る」でブリーズロッドを受け取り、左クリックで1点目、右クリックで2点目のブロックを選ぶ。
2. 一覧の「新規作成」でIDをチャットに入力する（英小文字・数字・`_`・`-`、32文字まで）。選択範囲があれば、そのままコース範囲になる。
3. 編集画面で、名前・範囲（杖の選択範囲から）・スタート地点（範囲内で接地した今の位置と向き）・制限時間・状態（下書き／テスト中／完成）を設定する。
4. ダイヤモンドブロックの上に立って「ゴールを登録／解除」を押す（複数登録可。登録済みの上で押すと解除）。
5. 必要なら「初期装備」で1〜3番に入れるアイテムを選ぶ（既定は1番に設置用ブロック。1番は必須）。以前の4番の設定は読み込み時に捨てられます。
6. 鉄の感圧板（重量感圧板・重）の上に立って「足元のトリガーを編集」を押し、アクションを追加する。
7. 「ルート（到達率）」で、スタートからゴールまで通るべき道に沿って点を置く（左クリック：今の位置を追加、右クリック：最後の点を削除、Shift＋右クリック：全削除）。到達率（%）の計算に使います。
8. 必要なら「設置可能箇所」でマーカー（黄緑の羊毛）を受け取り、ブロックを置いてよいマスに置く。ブロックは置かれず、そのマスが登録されます（登録済みのマスにもう一度置くと解除、ボタンのShift＋右クリックで全削除）。登録したマスがあるコースでは、本番・練習中にそれ以外の場所へブロックを置くと失敗になります（記録の理由は `PLACE`）。1つも登録しなければ、今までどおりどこにでも置けます。

杖を手に持っている間だけ、選択範囲（黄）・最後に開いたコースの範囲（水色）・スタート地点（黄緑の柱）・ゴール（白の枠）・トリガー（橙の枠）・ルート（赤紫の線）をパーティクルで表示します。設置可能箇所は小さい黄緑の羊毛（BlockDisplay）で、杖かマーカーを持った運営と、そのコースを遊んでいるプレイヤーにだけ見えます。

範囲・スタート・ゴール・制限時間・初期装備・トリガー・失敗条件・ルート・設置可能箇所を変えると、コースの**版（rev）**が1つ上がります（編集画面の本の説明に表示）。記録・自己ベスト・挑戦回数は版ごとに分かれます。名前・状態の変更では上がりません。
コースは `plugins\ParkourGauntlet\courses\<id>.json` に1ファイルずつ保存します。削除したコースは `courses\deleted\` に退避します。
読み込めないファイルは起動ログに出してスキップし、上書きしません（同じIDでの新規作成も拒否します）。

### アイテムテンプレート

一覧・編集画面の「アイテムテンプレート」で管理し、`plugins\ParkourGauntlet\templates.json` に保存します（全コース共通）。
「手持ちのアイテムを登録」でメインハンドのアイテムを個数・データごと登録するか、メイス・ウィンドチャージ・エリトラ等をワンクリックで追加します。
クリックで耐久値無限の切り替え、右クリックで名前変更、Shift＋右クリックで削除。メイスのテンプレートは、渡すときにウィンドバーストⅠ〜Ⅲを選びます。
渡したアイテムには内部タグ（テンプレートとレベル）が付き、「持っているか」はこのタグの完全一致で判定します。

### トリガーとアクション

登録した鉄の感圧板を踏むと、1回の挑戦につき1回だけ、アクションを上から順に実行します（1つのトリガーに18個まで）。

| アクション | 内容 |
|---|---|
| アイテム付与 | 完全に同じもの（テンプレート＋レベル）を持っていなければ渡す。渡す場所は「1番を上書き」「2・3番」「2〜3番の空き」（以前の「4番」は「2〜3番の空き」として扱う） |
| アイテム削除 | 指定テンプレートを消す。メイスは全レベルか指定レベル |
| mobスポーン | `minecraft:strider -84 -56 -37 {Age:0,Silent:1b}` のような summon の内容をチャットで入力。座標があればその位置、なければ今の位置。`Tags` は使用不可（追跡用に自動で付ける） |
| サウンド | 一覧から選ぶかIDを入力。音量・音程は編集画面で調整、本人にだけ鳴らす（本人の「コースの演出音」の音量設定が掛かる） |

スポーンしたmobは、失敗・リトライ・終了時に消します。ワールドには保存されず、クラッシュ後に残ったものは読み込み時に削除します。
mobのSNBTはMinecraftのバージョンで書式が変わることがあります。バージョン更新時はmobのアクションを確認してください。

## 参加者モード（本番・練習）

編集画面の「参加者モードで遊ぶ」（左クリック：本番、右クリック：練習）、または `/course play <ID>`・`/course practice <ID>` で開始し、`/course leave` で終了します。別のコースを始めると今のコースは自動で抜けます。運営は全コース、それ以外は「完成」のコースだけ遊べます（進行状況の仕組みができるまでは「完成」＝開放済み）。

- 開始時に位置・ゲームモード・所持品を `plugins\ParkourGauntlet\participants.json` に保存してから、スタートへ移動・Adventure・初期装備の状態にします。終了・ログアウト時に元へ戻します。サーバーが落ちた場合も次の参加時に戻します。
- スタート地点（練習ではセーブ地点）から位置が動くか、アイテムを使った（右クリック・設置・スイング）最初のクライアントtickを0として計測します。視点だけでは始まりません。
- 計測は `ClientTickEndEvent`（Paper）の受信数です。1秒以上届かない場合は「計測不能」と表示し、その挑戦は INVALID として記録します（自己ベストには使いません）。制限時間はクライアントtickで判定し、通知が止まった場合のためにサーバー時計でも制限時間の1.5倍で打ち切ります。
- 失敗条件：マグマ・範囲外（コースごとにオン／オフ）、死亡、時間切れ（本番のみ）、設置可能箇所以外へのブロック設置（登録があるコースのみ）。失敗すると本番はスタート、練習はセーブ地点（なければスタート）に戻ります。
- 戻るときは、設置用ブロックの足場・mobを片付け、装備・エフェクト・トリガーの発火状態を戻します。
- インベントリ操作・持ち替え・アイテムを拾うことはできません。

| スロット・キー | 本番 | 練習 |
|---|---|---|
| 1〜3 | コースのアイテム | 同じ |
| 1番を持ってQ | スタートへ（計測中ならリタイア。ゴール後はリトライ） | セーブ地点へ（なければスタート） |
| F | — | セーブ（地面の上のみ。1つ前のセーブは `/course undosave` で戻せる） |
| 5 | 練習に切り替え（砂糖。スタートから） | 本番に切り替え（レッドストーン） |
| 6 | — | 飛行のオン／オフ（羽。オンで光る。実際に飛んだ区間のタイムは無効） |
| 8 | プレイヤー表示の切り替え | 同じ |
| 4・7・9 | 空き（9番は今後メニューを置く予定） | 同じ |

- 情報はすべてアクションバーに出し、タイトル表示は使いません。部品は薄灰色の `|` で区切ります（例：`12.35s / 30s | 63.4% | [Q] リトライ`、練習は `練習 | 区間 4.20s | 63.4% | [Q] セーブ地点へ | [F] セーブ`）。Q・Fはプレイヤーの実際のキー設定で表示します。1番のアイテムの説明文にも書きます。
- ルートが登録されたコースでは到達率（%）を出します。本番はその挑戦で一番進んだ位置、練習は今の位置の%です。壁越しに先のルートへ近づいても%が飛ばないよう、今の位置に近い区間だけで判定します。
- 失敗しても理由などは表示せず、音だけ鳴らして戻ります。セーブの結果はチャットに出します。飛行・プレイヤー表示の切り替えは通知しません（アイテムの見た目で分かるため）。
- アイテムは入れ替えるスロットだけを直接書き換えます（`/item replace` と同じで、拾ったときのような弾む動きが出ない）。
- 時間は日本語でも `12.35s` の形です。
- 本番でゴールするとチャットにタイム・tick数・自己ベストとの差を出し、その場で待機します。
- 練習のセーブは位置・持ち物・エフェクト・トリガーの発火状態・その時点までの足場・mob（状態ごと）を保存します。ロードするとセーブ後に置いた足場だけ消えます。練習では時間切れになりません。
- 練習の区間タイムは、ロード（またはスタート）後に動いてから、次のトリガーかゴールまでです。記録には残りません。
- 本番の全試行をデータベースの `runs` に記録します（コース・版・プレイヤー・結果 CLEAR/FAIL/RETIRE/QUIT/INVALID・失敗理由・tick・実時間・到達率・開始／終了時刻・終了位置）。

## チャット翻訳

自由チャットを閲覧者ごとに翻訳します（個人メッセージ等は対象外）。

- 自動翻訳ON：翻訳文を `[訳]` 付きで表示し、ホバーで原文と元の言語を表示します。
- 自動翻訳OFF（初期値）：発言者のクライアントの言語と自分の翻訳先が違うとき、原文の後ろに `[翻訳]` ボタンが付きます。押した人にだけ翻訳文を表示します。
- 翻訳先の初期値は表示言語（UI言語）と同じです。設定は個人設定に保存され、`/settings` または次のコマンドで変更できます。

```
/translate              現在の設定を表示（運営には今日の送信文字数も表示）
/translate on|off       自動翻訳の切り替え
/translate lang <言語>  翻訳先（ja, en, ko, zh-CN, zh-TW, es, pt, fr, de, ru, it, th, vi, id）、ui で表示言語に戻す
```

翻訳エンジンは `plugins\ParkourGauntlet\config.yml` の `translation.engine` で切り替えます（変更後は再起動）。

| engine | 内容 |
|---|---|
| `mymemory`（既定） | MyMemory。キー不要。1日5,000文字、`mymemory.email` に連絡用メールを書くと50,000文字 |
| `libretranslate` | 自前のLibreTranslateサーバー（`libretranslate.url`、必要なら `api-key`） |
| `none` | 翻訳しない |

- 同じ言語の文や短すぎる文（かなを含む文を日本語へ、など）はAPIを呼ばず、同じ文はキャッシュから返して無料枠を節約します。
- 2.5秒（`timeout-ms`）以内に返らなければ原文と `[翻訳]` ボタンで表示します。無料枠を使い切ったらその日（UTC）は翻訳を止めます。
- 翻訳文はサーバーが書き換えた表示のため、受け手のクライアントで「改変されたメッセージ」の印が付く場合があります。サーバーログには原文が残ります。

## 多言語表示・個人設定

画面の文言は `src\main\resources\lang\ja.yml`・`en.yml`（MiniMessage形式）にあります。表示言語は個人設定 `ui_lang`（自動＝クライアントが日本語なら日本語、それ以外は英語）です。
`plugins\ParkourGauntlet\lang\<言語>.yml` に同じキーを書くと上書きでき、`/gauntlet reload lang` で読み込み直します。運営向けの画面（`editor.*`）は当面日本語だけです。

個人設定は `/menu` の設定画面か、次のコマンドで変更します。設定の一覧は `data/Settings.java` にあり、画面はこの定義から組み立てる想定です。

```
/settings                 一覧を表示
/settings <キー> <値>     変更（例：/settings sound.system 50）
/lang ja|en|auto          表示言語
```

| キー | 内容 | 値 |
|---|---|---|
| `ui_lang` | 表示言語 | auto / ja / en |
| `translate_lang` | 翻訳先 | ui（表示言語と同じ）/ 14言語 |
| `translate_auto` | 自動翻訳 | true / false |
| `sound.system` | システム音の音量 | 0〜100（10刻み） |
| `sound.course` | コースの演出音の音量 | 0〜100（10刻み） |
| `players.visible` | プレイヤー表示（8番のアイテムで切り替え） | — |

## メニュー（Dialog）

`/menu` でメニュー画面を開きます。画面はこのリポジトリの Dialog エディター（[dialog-editor/](dialog-editor/README.md)）で作り、書き出した `templates\*.json` を `plugins\ParkourGauntlet\menu\` に、`resourcepack.zip` をクライアントに入れて使います（配布の仕組みはまだありません）。プラグインが雛形からプレイヤーごとの画面を組み立てて送るので、設定画面には今の値が表示されます。雛形を差し替えたら `/gauntlet reload menu` で読み直します。
今つながっているのは「画面の移動」「✕で閉じる」「ロビーへ戻る」「エモート（BetterModel）」「設定」です。それ以外のボタンは「準備中」と出ます。詳細は [docs/design/menu-dialog.md](docs/design/menu-dialog.md)。

## 表示（TAB・スコアボード・名前）

- 名前は `[ 1 ] [ADMIN] 名前` の形で、チャット・TABに出します（頭上は `[ 1 ] 名前`）。名前の色はランク色です。**ランクの仕組みはまだないため全員ランク1、色も仮です。** `[ADMIN]` は権限 `gauntlet.display.admin`（既定OP）で付きます。
- 頭上の名前はプレイヤーに乗せたTextDisplayで表示し、バニラの名前は隠します。コース中は出しません。乗せたままだとワールドをまたぐテレポートができないため、コマンド実行時・ポータル・プラグインのテレポートの前に外し、0.5秒以内に付け直します。
- TAB：ヘッダーにロゴ、フッターに自分のPingと `Tips`（言語によらずこの表記。20秒ごとに切り替え）。並びは ADMIN → ランク → 名前。
- スコアボード：`Player:`・`Rank:`・`Playtime:`（見出しは金色）とサーバーIP。コース中は `Course:`（コース名）・`Best:`（自己最高の到達率。クリア済みなら `Clear ✓ タイム`、どちらもなければ `—`）・`Attempts:` を追加します。
- サーバー名・接続先は `config.yml` の `server.name`（既定 `Catena Online`）・`server.address`（既定 `mc.catenaonline.net`）。
- 名前の書式・11ランクの色・チャットの書式・TABのヘッダーとPingの色・スコアボードの行・サーバー一覧の説明（motd、空なら server.properties のまま）は `display.yml`（同梱の既定値を `plugins\ParkourGauntlet\display.yml` で項目ごとに上書き）で決まり、`/gauntlet reload display` で再起動せずに反映されます。Webエディター（`web/editor/index.html`）でプレビューしながら編集できます。手順は [docs/VPS_SERVER.md](docs/VPS_SERVER.md) の「表示設定」を参照してください。
- 透明化したプレイヤーは完全に見えません（チームの「味方の透明を見られる」をオフ）。防具・持ち物も、ほかの人には毎tick「なし」と送って隠し、頭上の名前も消します。TABには残ります。
- プレイヤー同士は干渉しません：押し合いなし（チームの衝突ルール）、攻撃・ノックバック（メイス・ウィンドチャージ・爆発を含む）なし、ほかのプレイヤーの飛び道具はすり抜ける、ポーション・釣り竿も効かない。ほかのプレイヤーが立っている場所にもブロックを置けます（自分の体の中や、mob・乗り物がいる場所は不可）。mobとプレイヤーの間は通常どおりです。
- 8番の「プレイヤー表示」で非表示にすると、ほかのプレイヤーはTABからも消えます（Paperの仕様）。

## ロビー

`config.yml` の `lobby.world` にワールド名を書くと有効になります（既定は空＝無効）。そのワールドにいるAdventure/Survivalのプレイヤー（コース外）は、**所持品がロビー用のホットバーに置き換わります**（1番：ブロック、8番：プレイヤー表示）。ブロックはどこにでも置け、`lobby.block-seconds`（既定10秒）で消えます。インベントリは動かせません。

## ローカルサーバー

以前の試作プロジェクト全体は `C:\mc\test-gauntlet` に移しました。新プロジェクトは `C:\mc\gauntlet` です。
新しいサーバーには以前のワールドと設定をコピーしました。試作プラグイン・リソースパック配布機能は移植していません。
自分の接続先は **`127.0.0.1:25575`**、Minecraft Java 26.3です。既存のOP・ホワイトリストを引き継いでいます。身内向けにLAN接続を受け付ける設定にしました。公開の残りの手順は [docs/FRIENDS_SERVER.md](docs/FRIENDS_SERVER.md) を参照してください。
旧サーバーと新サーバーは同じポートを使用するため、同時起動しないでください。

PowerShellでプロジェクトディレクトリから実行します。実行ポリシーは起動するプロセスだけに指定し、システム設定は変更しません。

```powershell
cd C:\mc\gauntlet
```

### HotSwap（再起動なしでコード変更を反映）

開発中は JetBrains Runtime（JBR）でサーバーを起動すると、変更したクラスを稼働中のサーバーへ直接反映できます。プラグインの unload/load は行いません。

```powershell
# 初回のみ: JBR 25 を run\jbr-25 に取得（SHA-512検証あり）
powershell -NoProfile -ExecutionPolicy Bypass -File .\prepare-jbr.ps1
# いつも通り配置してから HotSwap モードで起動
powershell -NoProfile -ExecutionPolicy Bypass -File .\prepare-server.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-server.ps1 -Hotswap
# コードを変更したら別ウィンドウで（コンパイル→変更クラスだけ反映）
powershell -NoProfile -ExecutionPolicy Bypass -File .\hotswap.ps1
```

- メソッド本体の変更に加え、フィールド・メソッドの追加削除、新しいクラスの追加にも対応します。
- `onEnable` で一度だけ行う処理（コマンド・リスナー登録、config 読み込み、スケジュール済みタスク）は再実行されません。`plugin.yml` やリソースの変更も対象外です。これらは `prepare-server.ps1` で配置し直して再起動してください。
- 反映状況は `build\hotswap` に記録されます。配置済み JAR が更新されると自動でリセットされます。

停止はサーバーコンソールの `stop`。この開発環境では次のローカル補助ツールでも停止できます。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\verify-server.ps1 -Action stop
```

## 保存と制約

CPと設置履歴は `run\paper-26.3\plugins\ParkourGauntlet\state.json` に保存します。
プレイヤーのプロフィール（初参加・最終ログイン・プレイ時間）・個人設定・案内の表示回数・本番の記録は `plugins\ParkourGauntlet\gauntlet.db`（SQLite）に保存します。SQLiteのドライバはPaperが起動時にMaven Centralから取得します（`plugin.yml` の `libraries`）。
以前の `records.jsonl`・`chat-prefs.json` は初回起動時にデータベースへ取り込み、`.migrated` を付けた名前で残します（旧記録の版は0、到達率なし）。
ログアウト・サーバー停止時に専用足場を片付け、起動時に残った履歴も回収します。CPは維持します。
設置前のBlockDataを記録し、リトライ時に戻します。記録後に別種類のブロックへ編集した場所は上書きしません。
同じ種類・同じBlockDataへの再編集は履歴と区別できません。専用足場を永久コースに転用する場合は、先にリトライで片付けてから普通のブロックで設置してください。

現段階では**実ワールドの足場**を使います。複数レーンの割り当てや他プレイヤーのゴースト表示は未実装です。
ピストン・爆発等で足場を移動／消去する運用は未対応です。CPの保存後に周囲の地形を変更した場合の安全なTP先の再選定も未実装です。
設置履歴はブロックごとに同期保存します。大人数・高速連続設置の負荷試験は今後の対象です。

権限は `gauntlet.admin`（既定OP）。他の保護プラグインの設置制限を強制解除する処理はありません。
サーバー全体の移動検証・飛行制限を緩める設定変更はしていません。

検証結果は [docs/VALIDATION.md](docs/VALIDATION.md)、実機テストは [docs/TESTING.md](docs/TESTING.md) を参照してください。

## Gitで保護する範囲

ソース、テスト、Gradleラッパー／依存ロック、補助スクリプト、手順書を管理します。
ワールド・サーバー設定・OP／ホワイトリスト・CPデータ等の `run/`、生成JAR・ログ等の `build/`、Gradleキャッシュは対象外です。
既存のワールドはディスクに保持しますが、Gitからは復元できません。
新しいチェックアウトでも旧試作を参照せず、`prepare-server.ps1` で指定ビルドのPaperを取得できます。Minecraft EULAへの同意と運用設定は別途必要です。

変更を保存する場合:

```powershell
git status
git diff
# 変更したファイルを明示して追加する
git add src/main/java/konqasasas/gauntlet/ParkourGauntletPlugin.java
git commit -m "変更内容"
```

ローカルGitの履歴は同じPC上にあります。PCの故障にも備えるには、後で別ディスクへのバックアップか非公開リモートへの保存が必要です。
